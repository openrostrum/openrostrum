| Judge / finding | Decision | Verified reason |

| Architecture — admin and portal independently implement participant-role transitions and primary repair | discard | Same verified reason as the simplicity finding: authorization, edit-window, role-policy, attachment, and notification contexts differ at the two transport boundaries. The shared invariants are explicit and independently covered by real-D1 tests; extracting a parameter-heavy state machine now would broaden the risk surface without correcting observed behavior. |
| Architecture — `Promise.allSettled`/broad catches treat every notification rejection as a committed mutation with warning | discard | Participant insertion commits before notification by design. Throwing afterward would falsely tell the user that a persisted submission/participant failed, and replay cannot safely infer that delivery must be retried. Every rejection is tracked with the exact participant ID and error, and the UI surfaces a non-destructive warning; provider failures also persist Email history. This is explicit post-commit failure semantics, not hidden failure. |
| Governance — schema/migration authorship conflicts with the normal integration-owner-only rule | discard | The finding correctly reads the static repository rule, but the lane assignment explicitly granted this feature worktree `pnpm db:generate` for slot 0009 and `ALLOW_SCHEMA_CHANGE=1` for `app/db/schema.ts`, `drizzle/`, and `drizzle/seed.sql`. The generation gap and later main merge were reconciled: 0008 remained Speaker CRM, 0009 chains from its snapshot, 0000–0009 applied locally, and the PR discloses both the exception and expected red guard. |
| Simplicity — portal and organizer duplicate participant-role state transitions | discard | The routes share invariants but not trust boundaries or policies: portal mutations require effective-participant ownership plus source-form close/min/max gates, while organizer mutations require active-event admin authorization, existing/new-contact attachment, and manual-null/form notification context. A late generalized state machine would expand parameters and regression surface without fixing an observed defect; route-specific real-D1 tests verify collision, promotion, and atomic batch behavior on both boundaries. |
| Simplicity — notification callers pass state that the service reloads | discard | The insert layer must pass `wasExistingContact`, which cannot be reconstructed after insertion and controls persisted form notification policy. It also passes only confirmed inserted participant IDs plus provenance; the service reload is deliberate defense-in-depth that rejects mismatched submission/event/contact/role context before provisioning access or mail. Narrowing the signature would remove validation context rather than meaningful complexity. |
| Simplicity — busy ConfirmButton branches could become a shared disabled prop | adopt | After the cold round, `origin/main` advanced with convergence sweep #78, which independently added the shared `disabled` prop. The required append-only main merge therefore replaced the lane's local busy branches with the shared primitive without this lane authoring an integration-owned UI change. |
