# CRM Completion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let organizers define organization-wide person fields, persist values on CRM profiles, and email exactly the checked directory people through the existing composer.

**Architecture:** Add a `recordType` discriminator to the shared field library and a `contact_answers` table keyed by organization, normalized person email, and field. A focused CRM-fields domain module owns scoped definition/value queries and writes. The existing contact composer gains an organization-directory selection source while retaining one preview/suppression/outbox send path.

**Tech Stack:** React Router 7 loaders/actions, React 19, Drizzle ORM on Cloudflare D1, Zod 4, Vitest in workerd, existing `~/ui` primitives.

## Global Constraints

- Use TDD: each behavior test must fail before its implementation is added.
- Migration slot is exactly `0010`; run `pnpm db:generate` with `ALLOW_SCHEMA_CHANGE=1`, never hand-author SQL or journal metadata.
- D1 has no interactive transactions; use one statement or `db.batch()` for atomic multi-writes.
- Every loader/action self-authenticates and scopes by active organization/event.
- Announcement email only uses the existing `sendAnnouncement` path.
- Contact definitions are organization-scoped only; values are organization-level, not attached to one event contact row.
- Existing session field consumers must explicitly exclude contact fields.
- Routes compose existing `~/ui` primitives only and disable mutations through `useBusy()`.
- Exactly one judge-loop round runs with suffix `-G1`; do not merge the PR.

- [ ] **Step 3: Add the schema contracts**

In `app/db/schema.ts`:

```ts
export const FIELD_RECORD_TYPE = ["session", "contact"] as const;

// on fields
recordType: text("record_type", { enum: FIELD_RECORD_TYPE })
  .notNull()
  .default("session"),

export const contactAnswers = sqliteTable(
  "contact_answers",
  {
    id: id(),
    organizationId: text("organization_id")
      .notNull()
      .references(() => organizations.id, { onDelete: "cascade" }),
    email: text("email").notNull(),
    fieldId: text("field_id")
      .notNull()
      .references(() => fields.id, { onDelete: "cascade" }),
    value: text("value").notNull(),
    createdAt: createdAt(),
    updatedAt: integer("updated_at", { mode: "timestamp" })
      .notNull()
      .$defaultFn(() => new Date()),
  },
  (t) => [
    unique("contact_answers_org_email_field_uq").on(
      t.organizationId,
      t.email,
      t.fieldId,
    ),
    index("contact_answers_org_email_idx").on(t.organizationId, t.email),
    index("contact_answers_field_idx").on(t.fieldId),
  ],
);
```

Add organization/field/contact-answer relations. Add a composite index on `fields(recordType, organizationId, eventId)` or equivalent scoped indexes generated by the schema.
