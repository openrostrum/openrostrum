# H9 full UX audit — 2026-08-11

Scope: public Sessions, Speakers, Agenda, Itinerary, Gallery, and embeds; speaker Submissions, Tasks, Profile, and Files; organizer review, accept, schedule, and email. Findings came from browser walkthroughs against seeded local D1 plus code and regression-test inspection. No remote service or owner account was used.

| Surface | Issue | Class | Fixed or reported | Reasoning |
| --- | --- | --- | --- | --- |
| Public Speakers and Gallery detail | Related session titles were plain text, so a visitor could not open the session from the speaker. | Navigation | Fixed | Session mentions now link to `/sessions/<eventSlug>?session=<id>`, the natural standalone destination. |
| Public Speakers and Gallery detail | Room names were plain text, so a visitor could not see the rest of that room's program. | Navigation | Fixed | Rooms now link to `/sessions/<eventSlug>?room=<roomId>`. |
| Public Sessions and Agenda detail | Speaker rows did not open the named speaker. | Navigation | Fixed | Speaker mentions now link to `/speakers/<eventSlug>?speaker=<id>`. |
| Public Sessions and Agenda detail | Room metadata did not expose room filtering. | Navigation | Fixed | Rooms now link to standalone Sessions with only `room=<roomId>`. |
| Public embeds | Detail links inherited the embed URL and could resolve inside an embed instead of the full public program. | Navigation | Fixed | Every embedded surface receives explicit standalone Sessions/Speakers bases; the embed's OS-pinned theme contract remains unchanged. |
| Public Itinerary | Session cards had no route to full session details. | Navigation | Fixed | Both day and My Schedule cards now link to standalone session detail. |
| Public Itinerary | Opening My Schedule discarded the selected day and supported search/track state. | State persistence | Fixed | The tab now preserves `day`, `q`, and `track` while setting `view=mine`. |
| Public Itinerary | Active filters could hide saved sessions from My Schedule. | State persistence | Fixed | My Schedule selects saved items from the unfiltered scheduled program; filters still apply to the browse view. |
| Standalone public program | Visitors had no visible way to choose light, dark, or system theme. | Accessibility / preference | Fixed | `ProgramShell` now exposes the shared tri-state theme control; embeds intentionally do not. |
| Standalone public header | The theme menu's default upward placement could move it outside the top-header interaction area. | Interaction | Fixed | The header opts into downward placement while preserving the shared component's existing default elsewhere. |
| Speaker Tasks list | A task's session mention was plain text. | Navigation | Fixed | A successfully joined submission now links to the portal-local submission detail. |
| Speaker Task detail | “For session” was plain text, forcing a return to Submissions and a second lookup. | Navigation | Fixed | The mention now links directly to the portal-local submission detail. |
| Speaker Tasks | Assignment foreign keys could produce a destination without a readable submission row. | Navigation integrity | Fixed | Links use the ID returned by the authorized `submissions` join and remain plain text when no joined row exists. |
| Organizer Sessions and Abstracts | Opening a detail and going Back lost exact search, status, type, and page state, including explicit page 1. | State persistence | Fixed | Detail links carry the exact list URL in an encoded `returnTo`; detail validates it against the intended admin-list allowlist. |
| Organizer central Submissions | Detail returned to the type-specific list rather than the central queue that opened it. | Navigation | Fixed | Row and title navigation now carry `/admin/submissions` plus its exact query as the origin. |
| Organizer submission deletion | Delete redirected to a default type list instead of the validated originating list state. | Navigation / feedback | Fixed | Delete now returns to the same validated `returnTo` destination. |
| Organizer submission revisions | “Show the full history” dropped the originating-list context. | State persistence | Fixed | The revisions query now retains the validated return destination. |
| Organizer submission schedule panel | “Place it from the Agenda” named the next action but did not link to it. | Navigation / copy | Fixed | Agenda is now a one-click link. |
| Organizer compose sent state | A successful send explained the result but offered no direct route to its delivery record. | Feedback / navigation | Fixed | The sent-state header now includes “View Email history”. |
| Organizer Email History | A stale or shared `page` beyond the result set rendered an empty table while matching email existed. | Pagination | Fixed | The loader counts first, clamps to the final page, and applies the clamped offset. |
| Organizer Speakers roster | Validation, duplicate warnings, unique-email errors, and save failures cleared the add-contact form. | Typed-work retention | Fixed | Every rerendering action result returns raw typed values and every field restores them. |
| Organizer CRM directory | Validation, foreign-event, duplicate/existing-person, and save-failure paths cleared the add-person form. | Typed-work retention | Fixed | All reproducible rerendering paths return and restore the six typed fields, including the selected initial event. |
| Organizer Agenda list | Session titles were plain text, so review/edit required leaving Agenda and finding the submission again. | Navigation | Fixed | List titles now link to `/admin/submissions/<id>`. |
| Organizer Agenda | Session search lived only in component state and disappeared on reload, Back, or a shared URL. | State persistence | Fixed | `q` is URL-backed; keystrokes replace the current history entry and preserve all unrelated Agenda parameters without resetting scroll. |
| Organizer multi-step editing | Review, participant, task, schedule, and email work has no product-wide unsaved-work policy. | Flow architecture | Reported | Solving this consistently needs a shared dirty-state/navigation policy rather than isolated route prompts. |
| Organizer central Submissions | The surface is capped at 100 recent rows yet reads like a canonical work queue, with no complete search/pagination contract. | Scale / information architecture | Reported | Removing the cap or redefining the surface changes loader, UI, and product semantics; this is structural work. |
| Organizer participant picker | Search is limited to a preloaded 1,000-contact set. | Scale | Reported | Real organizations can exceed the cap; complete server-backed search requires a new bounded query flow. |
| Organizer Agenda on narrow screens | The scheduling board does not provide a dedicated touch/narrow-screen operating mode. | Responsive workflow | Reported | A safe solution changes the scheduling interaction model, not just CSS. |
| Shared compact controls | Several dense controls are below comfortable touch size, but enlarging them locally breaks high-density tables and cards. | Accessibility / design system | Reported | The product needs one density and minimum-target policy across shared controls. |
| Speaker Profile and long forms | Navigating away can silently discard unsaved edits. | Typed-work retention | Reported | Reliable protection requires a shared dirty-form contract compatible with browser and React Router navigation. |
| Speaker Submissions | Search is client-only, limited to loaded rows, not URL-backed, and clears on reload. | Search / state persistence | Reported | Complete URL-backed search and pagination require a server query contract for the portal list. |
| Speaker Files | The file list has no search or pagination. | Scale | Reported | Production-size libraries need server-backed list controls and a bounded loader. |
| Speaker Tasks | The task list has no URL-backed filtering or pagination. | Scale / state persistence | Reported | This requires loader-level query semantics rather than a local mechanical link fix. |
| Speaker Task history | Upload and comment history is rendered without a bound. | Scale | Reported | A production-safe history needs pagination or incremental loading plus stable ordering. |
| Public Itinerary persistence | Local-storage write failures are swallowed while the UI continues to imply the schedule was saved. | Reliability / feedback | Reported | Correct behavior needs an explicit persistence state and recovery UX, not only an error string. |
| Public Itinerary hydration | Interaction before stored itinerary hydration completes can race the restored selection. | Reliability | Reported | Preventing lost early input requires a defined hydration/merge policy. |
| Organizer scheduled Agenda cards | Important card actions are hover-only and too small for reliable touch use. | Accessibility / responsive workflow | Reported | Making them persistent inside already narrow cards worsens density; address with the narrow-screen Agenda redesign. |
| Organizer CRM add-person | The rare concurrent same-email recovery branch returns the winner but not the user's typed values. | Typed-work retention / concurrency | Reported | A trigger-based test was rejected because SQLite rolls the trigger insert back with the failed statement; without a valid deterministic two-writer regression, strict TDD bars a production-only patch. |

## Highest-priority reported work

1. Define and implement a shared unsaved-work policy for organizer and speaker editing flows.
2. Replace the capped central Submissions pseudo-queue with an explicit, complete server-backed work queue.
3. Design a touch-safe narrow-screen Agenda operating mode, including persistent reachable card actions.
